Automated Cloud Governance & IaC Compliance Engine

A lab project that checks Terraform code against CIS-style rules to catch misconfigured S3 buckets and open security groups before merge.

TECH STACK: Terraform IaC CIS Benchmarks GitHub Actions Trivy Policy as Code GitOps
01

Challenge

In rapid development cycles, cloud infrastructure configurations often slip into production with critical security oversights due to manual review bottlenecks. Common vulnerabilities include:

  • Publicly readable or writable Amazon S3 buckets lacking server-side encryption or strict access control blocks.
  • Overly permissive AWS Security Group rules exposing sensitive ports (e.g., SSH port 22 or database port 3306) to the entire Internet (0.0.0.0/0).
  • Hardcoded secrets, API tokens, or database passwords committed directly into Terraform modules.
  • Late discovery of policy deviations during periodic compliance audits long after resources have already been deployed.
02

Environment

This infrastructure benchmark was designed and validated in an automated lab CI/CD testbed:

Infrastructure as Code

HashiCorp Terraform

Multi-account AWS resource definitions across networking, storage, compute, and IAM.

Compliance Standard

CIS AWS Foundations Benchmark

Formal baseline specifications for storage encryption, network perimeter control, and identity governance.

Pipeline Automation

GitHub Actions Workflows

Pre-merge pull request status checks executing syntax linting, security scans, and policy verification.

Security Scanning

Trivy & Static Analyzers

Automated secret detection and configuration flaw analysis embedded directly into CI runs.

03

Solution

> Automated Pre-Merge Policy Enforcement

Configured continuous compliance checks in GitHub Actions that parse Terraform code and generated execution plans prior to pull request approval. Any configuration conflicting with baseline security rules automatically halts the pipeline.

> Storage Security & S3 Public Block Guardrails

Implemented automated rule validation requiring S3 buckets to have server-side encryption enabled (AES-256 or AWS KMS) and public access blocks turned on. Any bucket definition permitting public read/write access triggers an immediate build failure.

> Network Perimeter & Security Group Ingress Auditing

Audits all Terraform security group ingress rules against CIS standards, disallowing wide-open 0.0.0.0/0 CIDR ranges for administrative or database ports and mandating restricted bastion or internal VPN subnet routing.

> Secret Detection & Artifact Scanning

Coupled with Trivy security scans to inspect IaC files and container manifests for embedded API tokens, passwords, and known package vulnerabilities before any code can be merged into main branches.

04

Results

The automated governance engine verified a fully shifted-left cloud security process within the benchmark pipeline:

  • ✓ Pre-Deployment Verification: Security rules evaluate infrastructure code directly in pull requests, intercepting misconfigurations before cloud resources are provisioned.
  • ✓ Elimination of Open Exposure: Automated blocker checks successfully catch open 0.0.0.0/0 security groups and unencrypted S3 storage definitions prior to merge.
  • ✓ Zero Hardcoded Credentials: Automated secret scanning prevents accidental credential leakage in version-controlled infrastructure templates.
  • ✓ Auditable GitOps Trail: Every compliance check and security validation is recorded as an immutable commit status check in GitHub.
